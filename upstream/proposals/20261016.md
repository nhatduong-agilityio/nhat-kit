| P-17 | Grill before planning | Deck §02 | Add | `/devkit:grill <idea>`: asks `AskUserQuestion` questions in rounds, each with a recommended answer, and looks up facts in the code and docs itself so that only real decisions reach the user. Stops when no assumption is left unstated, writes the decisions to `plans/<slug>/decisions.md`, then offers `/devkit:plan`. Today `plan` and `brainstorm` cap at 3 questions. | S | minor |
| P-18 | Force-push guard hook | Deck §04 ("hooks over reminders", "never force-push") | Add | PreToolUse `Bash` hook `block-force-push.sh`: exits 2 on `git push --force`/`-f`/`--force-with-lease` to the default branch, and on any push to `main`/`master`. Today this rule lives only in prose in `git-manager.md`. Add cases to `test-hooks.sh`. | S | minor |
| P-19 | Model tiers for agents | Deck §02 ("Opus advises, cheaper models run") | Improve | Set the frontmatter `model:` per role: `planner` and `code-reviewer` stay `inherit` (advisor tier); `fullstack-developer` → `sonnet` (builder); `researcher`, `tester` (run mode), and `deployer` → `haiku` or `sonnet` (runner). `cook` adds one line: the main session reviews every phase diff before it is committed. Benchmark one `cook` run before and after. | S | minor |
| P-20 | GitHub issues as an AI work queue | Deck §02 | Add + Improve | New `/devkit:issue bug\|feature`: refuses to file until it has symptom-first title, location, repro, expected vs actual, testable ACs, and area + severity labels; checks for duplicates with `gh issue list --search` first. `/devkit:task #N` claims the issue (assignee + `in-progress` label as an advisory lock), closes it only through the PR's `Closes #N`, and on failure removes the claim and comments, never closes. | M | minor |
| P-21 | Issue and PR templates | Deck §02 ("a stranger can act on") | Improve | Add `templates/github/ISSUE_TEMPLATE/{bug,feature}.yml` matching P-20's required fields. Extend `pull_request_template.md` with *How verified (paste output)*, *Screenshots/GIF*, `Closes #`, and a "one concern per PR" checkbox. `bootstrap` copies them. | S | patch |
| P-22 | Evidence as an artifact | Deck §03 | Improve | `ship` gate "real-app verification" and `task` step "verify": when the change is visible in the UI, drive it with `/verify` or `/claude-in-chrome`, take a screenshot of each state (a GIF for long flows), and publish the evidence as one artifact linked from the PR body. | S | minor |
| P-23 | Living CLAUDE.md conventions | Deck §01 | Improve | `templates/CLAUDE.md`: add sections for *Remotes & never-push rules* and *Removed / reversed (date + why)*. `conventions.md`: (a) update CLAUDE.md in the same commit that changes a convention; (b) keep each skill's changeable rules in a project file the skill reads, so changing a rule means editing a doc. `check` flags a CLAUDE.md that the last N convention-changing commits did not touch. | S | patch |
| P-24 | Personal memory in retro | Deck §04 ("zero saved memories") | Improve | `retro` sorts each correction into one of three places: project facts go to CLAUDE.md or rules, and personal preferences go to auto memory (`/memory`). Rules that must always hold become hooks. `check` reports when auto memory is off. Optionally `retro` reads `/insights` output as extra input. | S | patch |
| P-25 | Plan ↔ tracker sync | Deck §02 | Add | `/devkit:plan sync <plan.md>`: pushes plan phases out as GitHub issues (or as items on a Projects board) and pulls their states back into the plan. The plan owns scope and order; the tracker owns status. Depends on P-20. ADO and Trello are out of scope for now. | M | minor |
