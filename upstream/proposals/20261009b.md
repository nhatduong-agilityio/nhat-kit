## Spaces for v2.2.0

A "space" is a coherent release theme. Pick one; scope it to fit a single minor version.

### Space A — Security + Discoverability (recommended)

Items: P-14 (`security-scan`) · P-6 (`llms`) · P-15 (hook diagnostics)

All three are independent, each deliverable in one cook pass. Together they tell a story: "know what you're shipping, who can discover it, and that your hooks are healthy."

| Item | Value | Effort |
| --- | --- | --- |
| P-14 `/devkit:security-scan` | High — secrets and CVE checks are table stakes for any real project | M |
| P-6 `/devkit:llms` | Medium — useful for any project that exposes an API or ships a library | S |
| P-15 hook diagnostics | Medium — improves maintainability of the kit itself | S |

Total: 1M + 2S → comfortable minor release.

Suggested cook order: P-15 first (no new skill, pure scripts change), then P-6 (new skill, no agent), then P-14 (new skill + agent).

---

### Space B — Backend Depth

Items: P-9 (`/devkit:backend`) · P-10 (`/devkit:db`)

Highest long-term value for a full-stack engineer. Both are M-sized and share the same `fullstack-developer` agent. However, they require more upfront research (framework conventions vary widely) and risk scope creep.

**Best when:** the next project is a backend-heavy build and you want devkit to cover it end-to-end.

---

### Space C — Quality Gates

Items: P-7a (commit quality gate hook) · P-7b (LLM-judge in test-hooks.sh)

Tightens the kit's own engineering practices. Lower user-facing value than Space A but high confidence it will pay off during kit development.

**Best when:** hooks are causing friction or missed issues in day-to-day work.

---

### Space D — Docs Ecosystem

Items: P-16 (docs-manager agent) · P-6 (`llms`)

Lays the foundation for a future `/devkit:docs` skill. Lower immediate value since most projects use `/devkit:bootstrap` for initial docs and then manage them manually.

**Best when:** documentation maintenance is a recurring pain point.
